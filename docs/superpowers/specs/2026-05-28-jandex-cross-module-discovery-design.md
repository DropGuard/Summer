# Jandex-Based Cross-Module Bean Discovery

**Date:** 2026-05-28
**Status:** Approved

## Problem

`SummerProcessor` (the compile-time annotation processor) has hardcoded knowledge of framework beans. Specifically:

- `discoverFrameworkBeans()` reads `META-INF/summer-beans.txt` — a flat list of class names with no annotation, hierarchy, or method metadata.
- `discoverInterceptorBeans()` contains a hardcoded map: `Map.of("summer.tx.TransactionInterceptor", "summer.tx.Transactional")`. Adding a new framework module with interceptors requires editing the processor.

This makes the framework non-extensible: every new module that exposes beans or interceptors may require changes to the compiler module.

## Solution

Replace `summer-beans.txt` with Jandex `.idx` files generated by `jandex-maven-plugin` in every module (framework and user). The processor reads these indexes from the classpath for generic, metadata-rich discovery. No hardcoded framework knowledge.

## Design

### 1. Build-Time Index Generation

Every module adds `jandex-maven-plugin` (defined in parent POM `<pluginManagement>`, activated per module):

```xml
<plugin>
    <groupId>io.smallrye</groupId>
    <artifactId>jandex-maven-plugin</artifactId>
    <version>3.2.7</version>
    <executions>
        <execution>
            <id>make-index</id>
            <goals><goal>jandex</goal></goals>
        </execution>
    </executions>
</plugin>
```

Runs in `process-classes` phase. Produces `META-INF/jandex.idx` containing full class metadata: annotations, interfaces, superclasses, constructors, methods.

**Modules:** `summer-core`, `summer-aop`, `summer-web`, `summer-tx`, `summer-data-jdbc`, `summer-data-redis`, `summer-grpc`, `summer-validation-hv`, `summer-runtime`, and user application modules (e.g., `summer-example`).

### 2. SummerProcessor — Jandex-Based Discovery

#### 2.1 Load Composite Index

On first processing round, read all `.idx` files from the compiler classpath:

```java
ClassLoader cl = getClass().getClassLoader();
Enumeration<URL> urls = cl.getResources("META-INF/jandex.idx");
List<IndexView> indexes = new ArrayList<>();
while (urls.hasMoreElements()) {
    try (InputStream is = urls.nextElement().openStream()) {
        indexes.add(new IndexReader(is).read());
    }
}
CompositeIndex index = CompositeIndex.create(indexes);
```

#### 2.2 Generic Component Discovery

Replace `discoverFrameworkBeans()`:

```java
for (AnnotationInstance ai : index.getAnnotations(
        DotName.createSimple("summer.core.annotation.Component"))) {
    ClassInfo ci = ai.target().asClass();
    TypeElement te = processingEnv.getElementUtils()
        .getTypeElement(ci.name().toString());
    // Add to allBeans if not already collected from roundEnv
}
```

Also scan for meta-annotated components: `@Configuration`, `@RestController`, `@GlobalMiddleware` — by checking annotations on classes for the `@Component` meta-annotation.

#### 2.3 Generic Interceptor Discovery

Replace the hardcoded `knownInterceptors` map:

```java
for (ClassInfo ci : index.getAllKnownImplementors(
        DotName.createSimple("summer.aop.MethodInterceptor"))) {
    AnnotationInstance intercepts = ci.annotation(
        DotName.createSimple("summer.aop.annotation.Intercepts"));
    if (intercepts != null) {
        // Extract trigger annotation from @Intercepts.annotations
        // Register as interceptor bean
        TypeElement te = processingEnv.getElementUtils()
            .getTypeElement(ci.name().toString());
    }
}
```

Any module can now ship a `MethodInterceptor` with `@Intercepts` and the processor discovers it automatically.

#### 2.4 Configuration + Bean Discovery

From the index, find `@Configuration` classes and their `@Bean` methods without needing `summer-beans.txt`.

### 3. Runtime Path — ComponentScanner Simplification

**Before:** Reads `META-INF/jandex.idx` (framework) + `META-INF/summer-beans.txt` (user) + live package scanning (fallback).

**After:** Reads `META-INF/jandex.idx` from all JARs and the user module. Single unified mechanism. Live package scanning retained as dev-mode fallback with a log warning when `.idx` is missing.

Changes:
- Remove `summer-beans.txt` reading logic from `ComponentScanner`
- User module's `.idx` found on classpath like framework modules
- `CompositeIndex` from all `.idx` files is the single source of truth

### 4. Build Order

The phases are naturally compatible:

1. **`compile`** — APT runs `SummerProcessor`, reads `.idx` from dependency JARs (already built), generates `GeneratedAotContext`
2. **`process-classes`** — `jandex-maven-plugin` indexes this module's compiled classes into `.idx`
3. **`package`** — `.idx` is included in the JAR for downstream consumers

The current module's `.idx` doesn't exist when APT runs — but the processor sees current-module classes directly via `roundEnv`. Jandex is only needed for **dependency** modules.

### 5. New Dependency

`summer-compiler` adds:

```xml
<dependency>
    <groupId>io.smallrye</groupId>
    <artifactId>jandex</artifactId>
    <version>3.2.7</version>
</dependency>
```

(`summer-runtime` already depends on Jandex.)

## Deletions

| What | Where | Why |
|---|---|---|
| `META-INF/summer-beans.txt` generation | `SummerProcessor.generateBeanRegistry()` | Replaced by `.idx` |
| `summer-beans.txt` reading (APT) | `SummerProcessor.discoverFrameworkBeans()` | Replaced by Jandex index scan |
| Hardcoded `knownInterceptors` map | `SummerProcessor.discoverInterceptorBeans()` lines ~406-408 | Replaced by generic `getAllKnownImplementors` |
| `summer-beans.txt` reading (runtime) | `ComponentScanner` | Replaced by unified `.idx` loading |

## Migration Summary

| Concern | Before | After |
|---|---|---|
| Framework bean discovery (APT) | `summer-beans.txt` class names | Jandex `.idx` — full metadata |
| Interceptor discovery (APT) | Hardcoded map | Generic: `getAllKnownImplementors(MethodInterceptor)` + `@Intercepts` |
| Cross-module metadata | Class names only | Annotations, hierarchy, constructors, methods |
| Index generation | APT writes text file | `jandex-maven-plugin` in `process-classes` |
| Runtime scanning | `.idx` (framework) + `.txt` (user) + live scan | `.idx` everywhere, live scan as dev fallback |
| New module onboarding | May require processor changes | Add jandex plugin — auto-discovered |
